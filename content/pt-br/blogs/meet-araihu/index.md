A Arai Hû reúne projetos independentes de software aberto feitos em Go. Nosso trabalho inclui interfaces renderizadas no servidor, publicação de APIs e monitoramento auto-hospedado. Este blog é um espaço para explicar esse trabalho além de uma nota de versão ou de um README.

O nome vem do guarani. No [site da organização](https://araihu.com/pt-br/), descrevemos *arai hû* como uma nuvem preta ou escura. A frase que acompanha a marca é "Software para passar a trovoada." É uma boa imagem para o trabalho que nos interessa: ferramentas práticas para problemas que continuam existindo depois que a demonstração acaba.

## Úteis por conta própria, melhores em conjunto

Os projetos seguem uma direção simples. Cada um deve resolver um problema concreto por conta própria e continuar útil ao lado dos demais. Go é uma base comum, e interfaces renderizadas no servidor são uma escolha recorrente.

O [Goshtoso](https://github.com/araihu/goshtoso) oferece componentes de interface para aplicações Go feitas com templ. O [Goshtoso App Shells](https://github.com/araihu/goshtoso-app-shells) acrescenta layouts reutilizáveis, e o [Goshtoso Charts](https://github.com/araihu/goshtoso-charts) oferece gráficos para aplicações Go e templ.

O [Manja](https://github.com/araihu/manja) trabalha com documentação e publicação de OpenAPI. O [Balemoh](https://github.com/araihu/balemoh) se concentra em monitoramento auto-hospedado. São ferramentas para tarefas diferentes, com interfaces construídas sobre as mesmas bases.

Publicação também faz parte desse trabalho. O [Margo](https://github.com/araihu/margo) compila Markdown em HTML, PDF e apresentações estáticas. O [Gazeta](https://github.com/araihu/gazeta) acrescenta as regras editoriais de um blog mantido em Git. Este blog é um dos consumidores dessas ferramentas. Os artigos e a identidade ficam em um repositório separado, enquanto o comportamento reutilizável de publicação continua nos projetos de origem.

## O que cabe neste espaço

Usaremos este espaço para notas dos projetos, explicações sobre escolhas de projeto e relatos de experimentos. Um anúncio de versão pode dizer o que mudou. Um artigo permite explicar qual problema levou à mudança, o que tentamos e quais limites o resultado ainda tem.

O código e a documentação de cada projeto continuam sendo o lugar para conferir o comportamento atual. Um post registra uma decisão ou uma etapa do trabalho. Ele não substitui o repositório nem representa uma promessa sobre versões futuras.

Esta apresentação está disponível em inglês, português brasileiro e espanhol. Cada versão tem seu próprio endereço, e os links de idioma levam ao artigo correspondente quando existe uma tradução.

## Acompanhe o trabalho

Comece pela [visão geral dos projetos](https://araihu.com/pt-br/) ou explore os [repositórios da Arai Hû](https://github.com/araihu).
